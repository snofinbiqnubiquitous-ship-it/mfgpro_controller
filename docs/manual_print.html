QAD 99.7.1.1 受注入力 (Sales Order Maintenance) 完全自動化仕様マニュアル

AI指示用プロンプト・リファレンス ＆ システム開発・運用統合仕様書

1. システム概要と基本設計思想

本仕様書は、Progress 4GL / QAD CUI 端末（VT100 80桁×24行）における 99.7.1.1 (Sales Order Maintenance / xxsosomt.p) の自動入力を100%正確・安全に完遂するための完全リファレンスです。

【絶対原則 1】ブラインド送信（先走り送信 / Typeahead）の絶対禁止
Progress 4GLはサーバー側のDBトランザクションや画面描画により、ステップ間でコンマ数秒〜数秒の応答ラグが発生します。レスポンスを待たずに送信するとキー脱字や誤爆の原因となるため、必ず画面バッファの表示変化（固有のプロンプト・ポップアップ枠・カーソル位置）を検知してから次キー・データを送信（同期待ち受け制御）します。
【絶対原則 2】Order ID（受注番号）の自動採番と一連IDの管理
Step 1 の Order: 入力欄を空のまま Enter を送信すると、QADサーバー側で一意の最新番号（例: SO199401）が自動採番されます。
この採番された Order ID が、当該注文におけるヘッダー・全明細行・特記事項・最終合計を束ねる一連の共通管理IDとなります。一度の命令で複数のOrder IDを取得したり、指定なく既存のOrder IDを変更することは絶対禁止です。
【絶対原則 3】特記事項の運用方針（案C：全クリア置換）
得意先マスターに既定の特記事項が存在する場合、エディタ進入直後に <F8> (Clear) を送信して既定コメントを一括消去し、今回入力された新しい特記事項のみを1行目から登録します。
【絶対原則 4】Reason Code（理由コード 70 / 28）の確実な自動解決
登録単価がマスタ定価と異なる場合は定価差異コード 70 (MISC) を、納期が異なる場合は納期差異コード 28 (INTERNAL) を自動入力して <F1> で確定します。

2. 全体統合フローチャート (Start to Finish)

※サイドバー「送信」ボタン押下から Order ID自動採番、ヘッダー貼り付け、特記事項全クリア置換、明細3階層ループ、最終合計確定・正式コミットまでの完全な自動処理フローです。

3. ヘッダー一括貼り付け仕様 (Step 2 バッファ)

Sold-To 欄にフォーカスがある状態で、以下の改行区切りテキスト（10行）を一括ペーストします。

行 項目名 設定値ルール 説明・留意事項
Line 01 Sold-To customer_code 顧客コード（例: "20000900"）
Line 02 Bill-To customer_code 【重要】Sold-To と同一の顧客コードを入力
Line 03 Ship-To ship_to_code 納品先コード（例: "20000911"）
Line 04 Order Date 当日日付 (MM/dd/yy) システム当日付（例: "09/29/26"）
Line 05 Required Date 要求納期 (MM/dd/yy) サイドバー入力値（例: "09/30/26"）
Line 06 Promise Date "" (空行) Enterでスキップ
Line 07 Due Date 回答納期 (MM/dd/yy) サイドバー入力値（例: "10/01/26"）
Line 08 Perform Date "" (空行) Enterでスキップ
Line 09 Pricing Date "" (空行) 【必須】Enterでスキップ
Line 10 Purchase Order purchase_order 注文番号 / 発注番号（例: "test"）
Line 11 Remarks remarks 備考テキスト（例: "test"）

4. 明細 3階層グループ化ロジック (Step 6)

サイドバーから渡された注文データ（items）は、以下の階層構造に変換されてQADに登録されます。

[ { "line_no": 1, /* 第1階層: Ln (品番ごとに1行採番) */ "product_name": "BW0100D", "price": "130", /* 単価 (製品単位で一意) */ "length_groups": [ { "sl": 1, /* 第2階層: SL (長さごとに採番) */ "length": "600", "entries": [ {"ser": 1, "rolls": 1, "width": "250"}, /* 第3階層: ロール (幅・本数) */ {"ser": 2, "rolls": 1, "width": "120"} ] }, { "sl": 2, "length": "400", "entries": [ {"ser": 1, "rolls": 1, "width": "120"} ] } ] } ]

5. エラー処理・安全保護・トラブルシューティング

事象・エラー 発生原因 システムの自動対応 / 解決アクション
Category=... Press space 得意先マスターの業種カテゴリ警告 <Space> を自動送信して画面ロックを即座に解除。
Please confirm update スリット設定完了時の確認プロンプト 初期値 yes に対し <F1> または <Enter> を送信して確実に保存。
Reason Code 要求 定価差異または納期乖離 定価差異時は 70、納期差異時は 28 を自動入力して <F1> で確定。
既定コメントの残存 得意先マスターからの自動引用 Step 5 でエディタ進入直後に <F8> (Clear) を送信して全クリア置換（案C）。
与信・延滞警告 (Press space) 取引先の与信限度超過や請求書未回収 コミット後の Press space bar to continue を検知し <Space> を送信して解除。
画面待機タイムアウト 通信切断または予期せぬエラーモーダル 各工程で最大タイムアウトを設定。タイムアウト時は自動停止してエラー表示。

6. UI連携仕様（自作モダンターミナル）

  • サイドバー（F3 / Ctrl 2回押し）: 顧客情報・納期・明細テーブルを快適に入力。
  • 「リセット」ボタン（左下）: Required Date と due date は現状維持し、それ以外の入力欄を一括消去。
  • 「送信」ボタン（右下）: 押下時、バリデーションを経て QAD 99.7.1.1 完全自動入力マクロを直接起動。確認ダイアログで「はい」を押すと、Step 1〜6.3.0 までが自律実行される。
  • F3 シークレット出力チェックターミナル: 送信キーストロークのシミュレーションをリアルタイム表示。
